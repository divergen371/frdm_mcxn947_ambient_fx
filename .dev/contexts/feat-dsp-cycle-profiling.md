## 目的

1. FRDM-MCXN947とPCM5102Aによる48 kHzフルレートアンビエント・シューゲイザーDSPのビルド設定、IDE開発環境、およびエフェクト音質を実機試聴に基づいて追い込む。
2. 将来のPCM1808 24-bit ADCによるギター入力でも音質が崩壊しないよう、SAI1のI2S出力と内部DSPパイプラインを24-bit Q23精度と十分なヘッドルーム設計へ引き上げる。
3. 入力信号のアタックに反応して+1/+2オクターブとテンションコードを付与するポリフォニックシマーモードを実装して比較できるようにする。
4. 次フェーズの物理UI拡張に向け、ロータリーエンコーダとI2C OLEDディスプレイの設計書を整備する。

## 採用した設計と理由

- コンパイル最適化とIDE設定の整備を採用した。
  - `CMakeLists.txt` でSDK既定の `-fno-builtin` を除去し、`debug` は `-Og -g3`、`release` は `-Os -mapcs` を外して `-O3 -flto=auto` へ分離した。翻訳単位をまたぐインライン化とCortex-M33の1サイクル飽和命令 `__SSAT` により、ISR処理効率とデバッグ性を両立させた。
  - ホスト側Clang解析で `__builtin_arm_ssat` が未定義エラーになる問題に対し、`#if defined(__clang__) && !__has_builtin(__builtin_arm_ssat)` による標準Cフォールバックを入れて実機向け生成コードを劣化させずに静的解析エラーを解消した。
  - `.vscode/tasks.json` に `Release: Build`、`Release: Flash`、`Release: Build & Flash` を追加し、`.clangd` と `.vscode/settings.json` で `ms-vscode.cpptools` の競合機能を無効化して `clangd` へ一本化した。
- 揺れない広がりと酩酊感を両立するため、3相6 Hzコーラスを廃止し、純フィードフォワードのDimension Chorusと高域・低域独立波形のハーモニックパンニングトレモロへ分離した。
  - Dimension Chorusは逆相2系統ペアに±2.5 msの中心オフセットを与えてPure Wet出力とし、LFO交差点でのSide成分消失とDry二重加算による希釈を防いだ。
  - ハーモニックパンニングの帯域分割にはfc=600 Hz、Q=0.5の2次Linkwitz-Riley TPT SVFをQ28係数で実装し、高域・低域60度位相差と6種の独立LFO波形を備えた。Cortex-M33の `SMULL` / `SMLAL` 8命令へ展開されるためPowerQuadは使わずCPU直実行とした。
- Reverse GateとEarly Reflectionsを前段カスケード拡散オールパスと64タップ非周期素数FIRへ刷新した。
  - 16+16の等間隔・交互符号タップで発生していた24 dB超のコムフィルタ金属音とエコーの粒立ちを消すため、Reverse Gateには前段4段モジュレーション付きオールパス拡散と非交互極性32+32タップFIR、140 Hz HPFおよび10 kHz LPFのトーンシェーピングを導入した。
  - P1 Reverse Gateは `mix=165`、`decay=110` として原音アタックと255 ms逆スウェルの対比を明確化し、P8 Shoegaze Cathedralは `tap_level=215` かつFDN直列寄り励振として逆スウェルを増強した。
- Shoegaze Cathedralのこもりを解消するため、FDNとShimmerの帯域設計およびDimension送りを刷新した。
  - 48 kHzループで過剰だったFDNダンピングを緩和して180 Hz入力HPFを追加し、CathedralのDimension入力へ300 Hz HPFを入れて低域団子化を止めた。
  - ShimmerはFDN帰還を1/4へ抑え、Q8線形補間による-10 cents微フラットと0.28 Hzテープワウおよび3.5 kHz LPFを与えて、ギラつかずノスタルジックに減衰する余韻へ変更した。
- SAI1出力および全DSPパイプラインを24-bit Q23へ拡張し、ギター強入力保護を組み込んだ。
  - `AUDIO_BIT_WIDTH` を `kSAI_WordWidth32bits` へ変更し、BCLK=3.072 MHzの64fsフレームで上位24-bitを左詰め送出する構成とした。PCM5102Aと将来のPCM1808の双方にそのまま対応できる。
  - 全ディレイバッファを `int32_t` Q23化し、入力最前段25 Hz DCブロッカ、内部-6 dBヘッドルーム、Shimmerソフトサチュレータ、および最終段-2.5 dBFSニー付きソフトリミッタを導入した。除算はCortex-M33の32-bitハードウェア `UDIV` を使う形へ最適化した。
- 内蔵テスト音源のグライドコードを4弦独立エンベロープのストラム音源へ更新した。
  - `Fmaj7 -> G6 -> Asus4 -> G9sus4` の4小節ループとし、18 ms刻み計54 msのダウンストローク発音、6.2 msピックアタックランプ、下限張り付き無しの弦別自然指数減衰、`env^2` 倍音ダンピング、および0.85 Hz・最大-83 centsのアームグライドを実装した。
- 入力アタック連動の4ボイスポリフォニックテンションシマーを実装し、P9とP10の2プリセットを追加した。
  - 既存の `g_shim_buf[2048]` を共有したまま4本の読み出し位相を回し、高速エンベロープと遅延追従スローエンベロープの比較でストラム頭のみを自動正規化検出する。
  - P9 `Tension Choir Bloom` は `add9`、`sus11`、`6/9`、`m7` の4ボイシングと軽いクワイアグライドを備える。
  - P10 `Ruin Cathedral` は立ち上げグリッサンドを撤廃し、`maj7`、3本の非同期LFO（0.17 / 0.22 / 0.28 Hz）で無重力に漂うデチューン浮遊霊聖歌隊、`maj14`、`#11`、および高域 `SmoothRand` パンを組み合わせた廃墟聖堂モードとした。
- 次フェーズ用のハードウェア・ソフトウェア設計書を2本作成した。
  - ロータリーエンコーダ設計書を `docs/encoder-design.md` に作成し、EC11単体およびKY-040モジュールに対応した `J2` 偶数ピン配線と `SysTick` 1 ms Grayコード読み取り、DSPパラメータスムージングを定義した。
  - I2C OLED表示・UI設計書を `docs/oled-ui-design.md` に作成し、`LPI2C2` の `J2[18]` / `J2[20]` 配線とdirtyページ差分転送、波形アイコン付き3ゾーンUIを定義した。

## 却下した代替案と理由

- ハーモニックパンニングの2次SVFにPowerQuadコプロセッサを使う案は却下した。
  - L/R 2チャンネル合計でCortex-M33の `SMULL` と `SMLAL` 計8命令に収まり、1サンプル単位でPowerQuadレジスタを設定・回収するよりCPU直実行の方が高速かつ簡潔であるためである。
- P9 `Tension Choir Bloom` のグライドと `6/9`・`m7` ボイシングを撤廃して純粋5度圏・ポルタメント無しへ置き換える案は、ユーザー判断によりP10追加前の元のP9仕様へ戻した。
- ロータリーエンコーダ読み取りにハードウェア `QDC` またはGPIO外部割り込み `PINT` を使う案は却下した。
  - ピン配置の柔軟性確保と接点チャタリングによる音声割り込みジッタ防止のため、`SysTick` 1 msポーリングを採用した。

## 発見された制約

- KY-040エンコーダモジュールは基板上の10 kΩプルアップ抵抗が `+` 端子へ接続されているため、`+` 端子へは必ず `J3[8]` の3.3 Vを供給する必要があり、5 V接続および未接続はいずれも不可である。
- 秋月電子の2色LED・プッシュスイッチ付きロータリーエンコーダ用DIP化基板 `RECNV-2` は販売終了となっている。
- 4音和音入力に対して固定インターバルの多声ピッチシフトと低域からの長時間立ち上げグリッサンドを同時に掛けると、16声の半音クラスターと微分音スウィープが過剰になるため、P10では立ち上げグリッサンドを撤廃して非同期LFOによる中空浮遊へ変更した。
- `docs/dsp-load-measurement.md` に記録されているDWTサイクル実測値39.0%は16-bit・32タップFIR時点の数値であり、64タップFIR・24-bit Q23・4ボイスシマー追加後の実機サイクル数は再取得が必要である。

## 注意が必要な難所

- `soft_sat_s24` と `soft_limit_s24` の除算を64-bit整数除算へ戻すと、ソフトウェア除算ヘルパ `__aeabi_ldivmod` がリンクされてISRサイクル数が増加する。32-bit `uint32_t` 除算によるハードウェア `UDIV` 実装を維持する必要がある。
- アタック検出の `g_env_slow` を入力絶対値 `ax` から直接作ると、ピーク検波である `g_env_fast` との定常レベル差によってクールダウン終了ごとに誤再発火する。必ず `g_env_slow += (g_env_fast - g_env_slow) >> 12` のように `g_env_fast` を遅延追従させる構造を保つ。
- I2C OLEDとKY-040エンコーダを接続する際、電源ピンは必ず `J3[8]` の3.3 Vを使用し、`J3[10]` の5 Vを接続しない。

## PowerQuad の使い道（2026-11-22 合意）

PowerQuad は既存段を速くするために使わない。FDN、オールパス、Dimension Chorus、シマー、600 Hz Linkwitz-Riley TPT SVF はサンプル単位の閉路であり、PowerQuad の FIR / FFT はブロック完了待ち、バイクアッドは 1 サンプルのレジスタ往復が Cortex-M33 の `SMULL` / `SMLAL` より遅い。64 タップ Reverse Gate も素数遅延のまばらな読み出しであり、密な畳み込みではない。

使うなら新しいブロック処理の音としてだけ使う。候補は 512 点 FFT のスペクトル・フリーズ / ブラーと、実測インパルス応答の畳み込みリバーブ。`docs/dsp-load-measurement.md` の 39% は 16 bit・32 タップ時点の値で、余力が足りないから PowerQuad を入れる、という順序にはしない。

## テンション選択（2026-11-23 合意）

同じ入力シーケンスでもテンションの繰り返しが一定でないことは歓迎する。増やしたいのはボイシングの種類そのものより、「次に何を出すか」を演奏家のように選ぶ判断である。NPU もスペクトル重心・密度も、この判断の本体にはしない。

`update_tension_bloom_48k()` の `g_tension_voicing = (g_tension_voicing + 1U) & 3U` を廃止する。P9 の既存4役（Lydian add9、sus11、6/9、m7）は役割として残す。選択は短い文法にする。

- 直前と同じボイシングは基本的に避ける。4回に1回だけ動機として残してよい。
- `#11` や `m7` のあとには足さず、`add9` かシマーを一段薄くする休符へ解決する。
- `sus11` は解決の前に置き、連続させない。
- 同じ入力でも結果がずれるように、既存のゆっくりした LFO 位相を重みへ足す。乱数テーブルにはしない。

語彙を足すのはこの文法の穴だけにする。P9 には「何も足さないオクターブ」と「一度だけ出す `#11`」、P10 には既存の maj7 系を残したまま「一度引いてから戻る」を追加する。8種を順に回すのは採用しない。

重心と密度は、その後のバイアス（明るい和音では `#11` の重みを下げる）に限る。アタック検出、開花のスムージング、ピッチ処理は CPU のまま維持する。

調査レポート `reports/neutron-n1-16-shimmer-tension.md`（interaction `trun_e44108c55b304a308aac8445335971b6`）の結論は、NPU は条件付きで小さな INT8 CNN のイベント分類にだけ使えるが、この機能では CPU の文法を先にする、である。
